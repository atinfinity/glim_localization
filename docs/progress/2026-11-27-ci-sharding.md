# CI checks as parallel parts ([#64](https://github.com/atinfinity/glim_localization/issues/64))

- **Change**: the first step towards [#64](https://github.com/atinfinity/glim_localization/issues/64) beyond docs-only detection. Each architecture's checks now run as three parallel jobs instead of one.
  - Measured before the change (run 46009698963, amd64, 4-core runners): "Run checks" took 526 s, and the core ctest took 309 s of that. A 4-worker simulation of the logged test times gives 309 s, which matches the run. With stride sharding into N=2 shards, the test sums are 642 s and 590 s, and the simulated wall times are 164 s and 151 s. Everything else (colcon build and tests, interfaces, Python, replay) takes about 211 s. Target: about 240 s on amd64 (554 s today) and about 200 s on arm64 (443 s).
  - [`scripts/ci.sh`](https://github.com/atinfinity/glim_localization/blob/main/scripts/ci.sh) `--part all|core-K/N|rest`. The default, `all`, runs the same sequence as before and still prints `PASS: all checks`. `core-K/N` builds the core and runs the K-th of N ctest shards; `core-1/N` also runs the dependency check. `rest` builds the core without its ctest and runs everything after it. Each part except `all` ends with `PASS: part <part>`. A bad part exits 2 before anything runs. `--skip-deps` (used by `ci_local.sh`) still works, and `ci_local.sh` is unchanged: it always runs `all`.
  - [`scripts/build_core.sh`](https://github.com/atinfinity/glim_localization/blob/main/scripts/build_core.sh): `GLIM_LOC_CTEST_SHARD=K/N` adds `ctest -I K,,N` and keeps `--no-tests=error`, so an empty shard fails. `GLIM_LOC_CORE_TESTS=skip` builds the tests but does not run them. Both are checked before the configure step, and setting both at once is an error.
  - [`.github/workflows/ci.yml`](https://github.com/atinfinity/glim_localization/blob/main/.github/workflows/ci.yml):
    - A new `changes` job (amd64) does the docs-only detection and `image_inputs_hash.sh` once per run. Its outputs are `docs_only` and `hash`, and it keeps the draft condition.
    - `checks` and `checks-arm64` share their steps through the `check-steps` anchor. Each one runs the matrix `part: [core-1/2, core-2/2, rest]` with `fail-fast: false`, and is skipped for a docs-only PR. The architectures stay two separate jobs rather than one arch matrix, so each publish job waits only for its own architecture.
    - `build-and-test` and `build-and-test-arm64` keep their ids, which the ruleset requires, and now sum up the results. They run with `always()` and pass only if `changes` succeeded and the checks are `success`, or `skipped` with `docs_only == 'true'`. Any other result (failure, cancelled, an unexpected skip) fails them. A skipped required check would count as passing, so they must never be skipped on a non-draft run.
    - The publish jobs need `[changes, build-and-test(-arm64)]`. They build the tag from `needs.changes.outputs.hash` and first run `docker manifest inspect`. They push only when the registry says the tag is absent. If the registry errors persist after 3 tries, they do not publish, as before.
    - When the pull misses, every part builds the image, but only `rest` writes `cache-to`. Every part restores the ccache with the unchanged key, and only `rest` saves it on main pushes, since `rest` compiles everything the core parts compile, plus colcon.
  - [`docs/build.md`](https://github.com/atinfinity/glim_localization/blob/main/docs/build.md) and the CI paragraph in `CLAUDE.md` describe the parts and the summing jobs.
- **Decisions**:
  - Stride sharding (`-I K,,N`) rather than a hand-kept list: a new test lands in some shard automatically. [`scripts/tests/test_ci_parts.py`](https://github.com/atinfinity/glim_localization/blob/main/scripts/tests/test_ci_parts.py) checks that each matrix is exactly `core-1/N`..`core-N/N` plus `rest`, that both architectures list the same parts, and that the parts together run every step of `all` once. It also checks the `--part` parsing, the `ctest -I` arguments, and that the required jobs need the check job and use `always()`. A dropped shard therefore cannot silently lose tests.
  - Putting the dependency check in `core-1/N` balances it against `rest`, the longest part.
  - Each part rebuilds the core from ccache instead of passing build outputs between jobs, which keeps the jobs independent.
  - Matrix job outputs are last-writer-wins, so publishing no longer reads `missing` from a check job.
- **Verification** (local, Docker, amd64 host with 16 cores; build volume `glim_loc_cishard_build` copied from the main build volume, pinned image `glim_localization:shard-base` = the current main image, `CTEST_JOBS=8` because a second CI job shared the host; the tree was touched first):
  - `ci.sh --part core-1/2`: dependency check, `100% tests passed, 0 tests failed out of 187`, `PASS: part core-1/2` (165 s, including the rebuild).
  - `ci.sh --part core-2/2`: `out of 186`, `PASS: part core-2/2` (37 s).
  - `ci.sh --part rest`: `SKIPPED: core tests`, colcon 3 + 24 tests, interfaces, 340 Python tests, quick robustness suite and replay e2e, `PASS: part rest` (258 s).
  - `ci.sh` (default): `out of 373` (= 187 + 186), the same later steps, `PASS: all checks` (354 s).
  - These times come from a shared host and a warm volume, so they do not predict the runner times.
  - Host pytest (`uv run --with pytest==9.2.0 --with PyYAML==6.0.4`): `test_ci_parts.py`, `test_is_docs_only.py` and `test_ci_local.py` pass, 136 tests in total.
  - actionlint 1.7.12 (`docker run rhysd/actionlint`, with shellcheck) reports no findings, and `shellcheck scripts/ci.sh scripts/build_core.sh` is clean.
- **Review** (agent): no high or medium findings. Fixed: `ci.sh` now unsets `GLIM_LOC_CTEST_SHARD` and `GLIM_LOC_CORE_TESTS`, so an exported value cannot make `all` skip tests; the stale `ci_local.sh` comment. Left as they are:
  - the publish jobs now start on every main push (with `packages: write`) and skip the push after `docker manifest inspect` finds the tag;
  - when the image is missing, all three parts of an architecture build it (six builds instead of two). This happens only on Dockerfile changes.
- **GitHub** (PR #75, run 46022296142):
  - Attempt 1 built the image in every part, because the image of the #73 merge was not yet published: the parts took 8 to 20 min, of which "Run checks" took 132 to 177 s on amd64.
  - Attempt 3, with the published image: the whole run took 4 min 45 s (amd64 parts 3.4 to 4.5 min, arm64 2.2 to 3.4 min), against about 9 min before. That is slower than the 240 s estimate, mostly from the image pull and the job overhead per part.
  - Attempt 2 failed once in `rest` (amd64): `test_launch_r1.py` received an `/initialpose` from a test that ran in parallel. This is a test isolation problem that the parts do not change (the colcon tests run as before); it is followed up separately.
  - A failing shard (temporary PR #76, a deliberate `FAIL()`): it landed in `core-1/2` on both architectures. The other parts finished, and both required checks failed.
  - A cancelled run (#76 rerun): every part was cancelled, and both required checks failed rather than show as skipped.
  - A docs-only PR ([#81](https://github.com/atinfinity/glim_localization/pull/81), run 46036961539): the check parts were skipped, and both required checks passed with `SKIPPED: docs-only change`.
