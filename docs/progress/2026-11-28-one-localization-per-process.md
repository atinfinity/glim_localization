# One localization per process ([#13](https://github.com/atinfinity/glim_localization/issues/13))

- **Change**: `EstimateBridge::connect()` added three lambdas to GLIM's static callback slots and never removed them, and the R2 node connected in its constructor. A second component load mutated the slots while the first odometry thread dispatched them (a data race), and every load leaked one bridge. Now:
  - `glim_localization::ProcessClaim` (core, ROS-free, `util/process_claim.hpp`): an RAII process-wide claim in the shared core library, so the R1 extension module and the R2 component share one flag. `acquire(owner)` throws `one localization per process: already held by <owner>` while a claim is live; the destructor (or `release()`) releases it. Its state is never destroyed, so a claim released during static destruction (an R1 bridge that stays in the slots) is safe.
  - `EstimateBridge::connect(bridge, owner)` takes the claim before it touches the slots and keeps the ids from `CallbackSlot::add`. `disconnect()` removes them and releases the claim. At GLIM 1a197c9, `CallbackSlot::remove(id)` sets the entry to an empty `std::function` (the vector does not shrink, so ids stay valid); `call()` skips empty entries. It is not thread-safe either, so it runs only when no odometry thread does.
  - R2: the constructor connects first, so a second load fails before it declares anything. The destructor disconnects after `stop()` has joined the odometry thread, so the component can be unloaded and loaded again.
  - R1: connects in `create_subscriptions` and never disconnects; the claim is held for the life of the process.
- **Decisions**:
  - The guard is not in the `OdometryEstimationLocalization` constructor: core tests hold several live instances on purpose, and the core's own static registry (resets, wheel odometry, `loaded_map`) is under a mutex. The registration in GLIM's unguarded slots is what must be unique.
  - R1 behavior when the claim is held (checked in glim_ros2 4d4ec52): `create_extension_module` catches an exception from the extension constructor and returns null, and `GlimROS` then logs `failed to load` and runs on without the extension. `create_subscriptions` is called from `GlimROS`'s constructor without a try, so the exception from `connect()` leaves it: `glim_rosnode` and `glim_rosbag` (`make_shared<GlimROS>` outside any try) end through `std::terminate`, whose handler prints the `what()` to stderr; a component container refuses the `glim::GlimROS` load with the message. The claim therefore stays in `create_subscriptions` (a refusal, not a silent run without localization output), and the extension logs the message with spdlog before it rethrows, so it is also in GLIM's log.
  - In a container, the second R2 LoadNode answers `success=false` with `Component constructor threw an exception: one localization per process: already held by R2 node /<first name>` (rclcpp_components wraps the constructor exception).
  - Each unload leaves three empty entries in the slot vectors (GLIM's `remove` does not erase); a few bytes per load, not a leak of the bridge or its publisher.
- **Verification** (Docker, amd64, `glim_localization:dev`): `scripts/docker_run.sh scripts/ci.sh` ends with `PASS: all checks`. New tests:
  - `test_process_claim` (core gtest): a second acquire throws and names the holder; a release (scoped or explicit) allows a new acquire; a move keeps one claim; 16 racing threads give exactly one winner, 50 rounds.
  - `test_estimate_bridge` (ROS gtest, isolated): a second `connect` throws with the message and its bridge gets no callbacks; connecting the same bridge twice is a `logic_error`; after `disconnect` the slot calls no longer reach the bridge, and a new connect succeeds and receives them.
  - `test_r2_single_instance` (launch test, isolated runner): in a `component_container`, the second LoadNode returns `success=false` with the message; after the first is unloaded, a load succeeds. No map or bag.
- **Open**: the other items of [#13](https://github.com/atinfinity/glim_localization/issues/13) (bounded input queue, clock jumps, result drain period, ...).
