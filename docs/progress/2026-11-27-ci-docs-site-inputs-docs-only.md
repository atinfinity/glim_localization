# Docs site inputs count as docs-only in CI ([#64](https://github.com/atinfinity/glim_localization/issues/64))

- **Change**: the first task of [#64](https://github.com/atinfinity/glim_localization/issues/64). A change to only the docs site inputs no longer runs the Docker build and tests on amd64 and arm64. [#60](https://github.com/atinfinity/glim_localization/pull/60) changed only `zensical.toml` and a progress entry, and its two runs took 7m46s and 5m33s, while its docs build took 17 s.
  - [`scripts/is_docs_only.sh`](https://github.com/atinfinity/glim_localization/blob/main/scripts/is_docs_only.sh) also accepts `zensical.toml`, `requirements-docs.txt`, `scripts/docs_site_index.py` and `.github/workflows/docs.yml`, matched as exact paths. Its other behaviour is unchanged: NUL-separated input, an empty list is not docs-only, and any other path makes the change non-docs-only.
  - [`.github/workflows/ci.yml`](https://github.com/atinfinity/glim_localization/blob/main/.github/workflows/ci.yml): the `paths-ignore` of the push trigger has the same four paths. The `pull_request` trigger still has no paths filter, so `build-and-test` and `build-and-test-arm64` report on every PR (their steps are skipped for a docs-only PR). The comments name the list and point to the detector.
  - [`scripts/ci_local.sh`](https://github.com/atinfinity/glim_localization/blob/main/scripts/ci_local.sh) already runs the detector on `git diff --name-only --no-renames -z <merge-base> HEAD`, only for a clean tree. A site input change now prints the same "SKIPPED build and tests, docs-only change" line and records no pass, like any docs-only change. The header comment says what docs-only means and that the site is not built there. The code is unchanged.
  - [`docs/build.md`](https://github.com/atinfinity/glim_localization/blob/main/docs/build.md) describes the docs-only rule.
- **Decisions**:
  - This reverses the decision in [2026-11-26-docs-site.md](2026-11-26-docs-site.md) to leave the site inputs non-docs-only. The C++ checks do not read these files, and `docs.yml` builds the site with `--strict` when any of them change.
  - Exact paths rather than patterns (for example `requirements*.txt` or `scripts/docs_*`): `scripts/requirements.txt` is an image input, and any other script under `scripts/` must keep running the full checks.
  - A rename lists both paths (`--no-renames`), so moving code into a site input runs the full checks, as moving code into `docs/` does.
  - The tests read `ci.yml` and `docs.yml` with PyYAML (already pinned in `scripts/requirements.txt` through evo), so the detector, the push `paths-ignore` and the docs workflow trigger cannot drift apart unnoticed.
- **Verification** (host, no Docker; `uv run --no-project --with pytest==9.2.0 --with PyYAML==6.0.4`):
  - `pytest scripts/tests/test_is_docs_only.py scripts/tests/test_ci_local.py`: 102 passed. The new cases: each site input alone and with a progress entry, each site input with code, lookalikes that stay non-docs-only (`scripts/other.py`, `scripts/tests/test_docs_site_index.py`, `docs.yaml`, `zensical.toml.bak`, `sub/zensical.toml`, `scripts/requirements-docs.txt`, `requirements.txt`, `ci.yml`), a rename of code into `scripts/docs_site_index.py`, a commit with only `zensical.toml` and a page, the push `paths-ignore` list and the absence of a PR paths filter, every `docs.yml` trigger path being docs-only, and `ci_local.sh` skipping a `zensical.toml` or `scripts/docs_site_index.py` change without a recorded pass. The existing cases (a docs file, a rename from code into `docs/`, a mix with code, empty input) still pass.
  - With the old detector, 6 of the new tests fail.
  - These tests run in `scripts/test_python.sh` (pytest over `scripts/tests`), which `scripts/ci.sh` runs; no wiring was needed. The Docker run of `scripts/ci.sh` was not done here.
- **Generator tests in the docs workflow**: a PR that changes only `scripts/docs_site_index.py` (with docs) now skips `ci.sh`, which ran `scripts/tests/test_docs_site_index.py`. `docs.yml` now runs that file with pytest 9.2.0 (the pin in `scripts/requirements.txt`) before the strict build.
- **Open**:
  - The later tiers of [#64](https://github.com/atinfinity/glim_localization/issues/64) are not done: Python-only changes under `scripts/` (Python tests, the quick robustness suite and e2e, no C++ rebuild) and changes only under `glim_localization_ros2/` (skip the core tests, which needs the core build cached). Whether they are worth it still needs measuring.
