# Wheel odometry input in R1 ([#14](https://github.com/atinfinity/glim_localization/issues/14))

- **Change**: the R1 GLIM extension (`localization_extension.cpp`) subscribes to `localization_ros.wheel_odom_topic` and feeds the twists to the odometry, as the R2 node does since [#53](https://github.com/atinfinity/glim_localization/pull/53). `scripts/replay_to_bag.py --wheel-odom` writes `/wheel_odom` from the ground truth, and the R1 launch test runs with wheel odometry on.
- **Core**: two static functions on `LocalizationCallbacks`, next to `request_reset` and `loaded_map`, because the extension does not own the odometry:
  - `insert_wheel_odom(stamp, linear, angular)` forwards to every live instance under the registry lock and returns true if one took the sample;
  - `wheel_odom_enabled()` is true if a live instance has wheel odometry enabled. The instance gets a public `wheel_odom_enabled()` accessor for it.
- **Config** (`localization_ros` in `config/r1/config_ros.json`): `wheel_odom_topic` (`""`), `wheel_odom_child_frame_id` (`"base_link"`) and `wheel_odom_time_offset` (`0.0`), with the meaning they have in R2. There is no `wheel_odom_qos`: GLIM's `TopicSubscription` subscribes with reliable, depth 100, and GLIM is not modified.
- **Decisions**:
  - The conversion is `convert_wheel_odom` of `wheel_odom_input.hpp`, shared with R2, so both reject the same messages.
  - The extension decides whether to subscribe when glim_ros2 asks for its subscriptions, after the odometry module is loaded. A topic set while no live odometry has `wheel_odom_enabled` gets a warning and no subscription, as in R2. A non-finite `wheel_odom_time_offset` gets an error and no subscription (R2 fails configure; R1 has no configure step to fail).
  - Rejects are warned about at most once per 5 s (steady clock; the extension has no node clock of its own). The counts of received, rejected and dropped messages are logged when the extension is destroyed.
  - `replay_to_bag.py --wheel-odom` takes the twist of the IMU frame from `traj_gt.txt` by central differences (one-sided at the ends), at the ground-truth stamps (the frame stamps, 10 Hz in the synthetic data). It matches a config with the identity `wheel_odom_T_imu_base`. The pose field is the ground truth; the consumers ignore it.
- **Tests**:
  - Core `WheelOdometryIsForwardedToLiveInstances`: no instance, a disabled one, an enabled one (a sample not newer than the last is not taken), and none after destruction.
  - `test_replay_to_bag.py`: the twist of a turning trajectory in the body frame, one message per ground-truth pose, and the errors without enough ground truth.
  - `r2_helpers.R2Client.play_and_wait` plays only the topics it is given (`ros2 bag play --topics`). It played the whole bag before, so the fixture's new `/wheel_odom` reached `test_r2_wheel_odom`, which expects no wheel input from the bag.
  - `test_r1_extension` runs with `wheel_odom_enabled` and `wheel_odom_topic: /wheel_odom` on the fixture bag, which now has `/wheel_odom` (`scripts/test_colcon.sh`). It checks the subscription log line and `wheel_factors > 0` in the last status, with the existing pose and accuracy bounds. It sets `glim_ros.playback_speed` to 2: `glim_rosbag` hands bag messages to the extension as it reads them but queues the frames, and at the default 100x the reset of the 5 s `/initialpose` could clear the wheel samples of most later frames.
- **Verification**: `scripts/docker_run.sh scripts/ci.sh`, Docker, amd64: all checks pass (335 core tests, 23 `glim_localization_ros2` tests including the linters, the Python tests, the replay e2e). `test_r1_extension`: 121 of 121 poses, worst error 0.016 m and 0.080 deg, 69 wheel factors after the last reset (1 gated, 0 missing). `test_r2_wheel_odom` unchanged: `received 7, rejected 2, dropped by the odometry 0`.
- **Open**: wheel input in the replay dataset (`bag_to_replay.py`, `glim_localization_replay`) and its evaluation with and without wheel odometry, the twist covariance as the factor noise, and the DEGRADED/LOST rules.
- **No result video**: the change is input plumbing; a comparison with and without wheel odometry comes with the replay dataset input.
