# Project site with Zensical on GitHub Pages ([#15](https://github.com/atinfinity/glim_localization/issues/15))

- **Change**: the Markdown under `docs/` is published as a project site, built with [Zensical](https://zensical.org/) and deployed to GitHub Pages at <https://atinfinity.github.io/glim_localization/>.
  - [`zensical.toml`](https://github.com/atinfinity/glim_localization/blob/main/zensical.toml) at the repository root: `docs_dir = "docs"` and a fixed navigation, mapped to the existing pages: Overview (`index.md`, from the README), Getting started, Build (Docker) (`build.md`), Map preparation (`maps.md`), Offline replay and evaluation (`replay.md`), Simulation evaluation, ROS 2 (`ros2.md`), Configuration reference, Limitations (`status.md`), Design (`DESIGN.md`) and Dependencies.
  - Home page: Zensical needs a `docs_dir` other than the root, so the README cannot be a page as it is. [`scripts/docs_site_index.py`](https://github.com/atinfinity/glim_localization/blob/main/scripts/docs_site_index.py) writes `docs/index.md` from it before each build, rewriting `docs/<path>` links to `<path>` and other repository paths (`CONTRIBUTING.md`, `CITATION.cff`) to GitHub URLs. The generated file and the build output `site/` are ignored by git. Tested in `scripts/tests/test_docs_site_index.py`.
  - Mermaid: Zensical's default Markdown extensions include `pymdownx.superfences` with the `mermaid` custom fence, so the config keeps the defaults; the diagrams in the README and `DESIGN.md` render as `<pre class="mermaid">`.
  - [`requirements-docs.txt`](https://github.com/atinfinity/glim_localization/blob/main/requirements-docs.txt) pins `zensical==0.1.3` and its dependencies (from `pip freeze` in a clean Python 3.12 venv).
  - [`.github/workflows/docs.yml`](https://github.com/atinfinity/glim_localization/blob/main/.github/workflows/docs.yml): runs when the site inputs change (`docs/**`, `README.md`, `zensical.toml`, `requirements-docs.txt`, the generator, the workflow). Pull requests only run `zensical build --clean --strict`, which aborts on any warning (a broken link or anchor). A push to main, or a manual run on main, also uploads `site/` with `actions/upload-pages-artifact` and deploys it with `actions/deploy-pages`. Actions are pinned to commit SHAs; the build job has `contents: read`, the deploy job only `pages: write` and `id-token: write`.
  - One link that left `docs/` (`../CONTRIBUTING.md` in `getting_started.md`) is now a GitHub URL; no page was otherwise changed for the site.
- **Decisions**:
  - `docs/PROGRESS.md`, `docs/progress/` and `docs/IMPLEMENTATION_PLAN.md` stay out of the navigation (`not_in_nav`) but are still built: the README, `status.md` and `DESIGN.md` link to them, and excluding them (`exclude_docs`) would break those links in the strict build.
  - There is no separate configuration reference page, and writing one would rewrite the docs. The navigation entry points to the configuration example in the design (section 5.5) by its site URL, because a navigation entry with an anchor is not resolved as a page; the ROS parameters are in the ROS 2 page.
  - `scripts/is_docs_only.sh` and the docs-only skip of the C++ CI stay as they are. The site build is a separate workflow that checks the docs, and the C++ checks have nothing to check in a docs-only change. The new non-Markdown inputs (`zensical.toml`, `requirements-docs.txt`, the generator) are not docs-only, so a change to them runs the C++ CI too, which is harmless.
  - The generated home page is preferred to a hand-written `docs/index.md` (two copies of the overview to keep in sync) and to including the README with `pymdownx.snippets` (its links would stay relative to the root and break).
- **Verification** (host, Python 3.12 venv with `requirements-docs.txt`, no Docker):
  - `scripts/docs_site_index.py && zensical build --clean --strict`: "No issues found"; 24 pages and `404.html`.
  - The strict build catches broken links: a link to a missing anchor added for the test failed it ("anchor does not exist"), and before the fix above `../CONTRIBUTING.md` failed it ("page does not exist").
  - An extra check of every local `href` and `src` in the built HTML (target file and anchor) found no broken link. The only misses were the root-absolute links of `404.html`, which resolve under `/glim_localization/` once deployed, and an HTML-entity-encoded `mailto:` link in `DEPENDENCIES.md` that the check does not decode.
  - `pytest scripts/tests/test_docs_site_index.py scripts/tests/test_is_docs_only.py`: passed.
- **Review fixes**: the deploy job is gated on `vars.PAGES_ENABLED`, as `release-please.yml` is gated on its App variable. The home page generator no longer rewrites inline code spans or `~~~` fenced blocks, and a root-absolute path (`/CONTRIBUTING.md`) is a repository path (tests in `test_docs_site_index.py`). Not changed: the Configuration reference nav entry is an absolute site URL that the strict build cannot check; it needs updating if section 5.5 of `DESIGN.md` is renamed.
